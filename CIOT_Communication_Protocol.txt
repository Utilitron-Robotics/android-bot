# Protocol Overview

This protocol is primarily used for data interaction with the algorithm layer of the general chassis, enabling users to display data and issue commands. Network communication is implemented via WebSocket, with data exchanged in JSON string format.

WebSocket belongs to the server-side push technology, which is essentially an application layer protocol that can realize full-duplex two-way communication of persistent connections.

Advantages:
1. Do not send HTTP requests frequently, only need to send an HTTP request for websocket handshake
2. The full-duplex channel breaks through the limitation that only the client can request the server
3. It can be passed while generating data, without waiting for data generation to be completed
4. WebSocket data transmission is based on data frames and can be transmitted in fragments

---

# Common Communication Format

The computer communication program mainly has the following operations:
- Publish information registration
- Publish specific data
- Log out of the publication information
- Subscribe to topic data
- Data return
- Unsubscribe from topic data
- Call the service interface

---

# Publish Information Registration

Before the client publishes data to the server, it needs to register the publication information.

```json
{
  "op": "advertise",
  "id": "<string>",        // optional
  "topic": "<string>",
  "type": "<string>"
}
```

---

# Publish Specific Data

Publishing is valid only after registration.

```json
{
  "op": "publish",
  "id": "<string>",        // optional
  "topic": "<string>",
  "msg": <json>
}
```

---

# Unregistering Publication Messages

```json
{
  "op": "unadvertise",
  "id": "<string>",        // optional
  "topic": "<string>"
}
```

---

# Subscribe to Topic Data

```json
{
  "op": "subscribe",
  "id": "<string>",                  // optional
  "topic": "<string>",
  "type": "<string>",
  "throttle_rate": <int>,            // optional, milliseconds (default 0)
  "fragment_size": <int>,            // optional, split threshold
  "compression": "<string>"          // optional, "png" for map compression
}
```

---

# Complete Package Data Reception

```json
{
  "op": "publish",
  "msg": "<string>",
  "topic": "<string>"
}
```

---

# Fragmented Data Reception

```json
{
  "op": "fragment",
  "id": "<string>",
  "topic": "<string>",
  "data": "<string>",
  "num": <int>,
  "total": <int>
}
```

---

# Unsubscribe from Topic Data

```json
{
  "op": "unsubscribe",
  "id": "<string>",        // optional
  "topic": "<string>"
}
```

---

# Service Request Interface

```json
{
  "op": "call_service",
  "id": "<string>",                  // optional
  "service": "<string>",
  "args": <list<json>>               // optional
}
```

---

{
  "op": "service_response",

## Obtain Robot Coordinates (Timing Trigger)

Subscribe:
```json
{
  "op": "subscribe",
  "id": "get_pose",
  "topic": "/robot_pose",
  "type": "geometry_msgs/Pose2D"
}
```

Response:
```json
{
  "topic": "/robot_pose",
  "msg": {
    "x": 0.009,
    "y": -0.047,
    "theta": 0.0114
  },
  "op": "publish"
}
```
- x: Global X-axis position (meters)
- y: Global Y-axis position (meters)
- theta: Direction in radians

Unsubscribe:
```json
{
  "op": "unsubscribe",
  "id": "get_pose",
  "topic": "/robot_pose"
}
```

# Release Class (Client → Server)

## Speed Control Command

Advertise:
```json
{
  "op": "advertise",
  "id": "velocity_control",
  "topic": "/cmd_vel_mux/input/teleop",
  "type": "geometry_msgs/Twist"
}
```

Publish:
```json
{
  "op": "publish",
  "id": "velocity_control",
  "topic": "/cmd_vel_mux/input/teleop",
  "msg": {
    "linear": { "x": 0.2 },
    "angular": { "z": 0 }
  }
}
```

Speed control:
- linear.x positive = forward (m/s)
- linear.x negative = backward
- angular.z positive = clockwise rotation (rad/s)
- angular.z negative = counterclockwise
- Both 0 = stop

A single release speed lasts for 0.6 seconds. Do not always publish zero speed.

# Service Class

## Program Control Framework

Request:
```json
{
  "op": "call_service",
  "id": "service_node_manager_control",
  "service": "/node_manager_control",
  "args": {
    "building_name": "csst",
    "floor_num": "2",
    "cmd": 0,
    "args": 0
  }

```

cmd values:
- 0: Open mapping (available in positioning/navigation mode)
- 1: Continue mapping (reserved)
- 2: Restart mapping (reserved)
- 3: Save map and corresponding information
- 4: Turn on location navigation (available in mapping mode)
- 7: Switch map (available in positioning/navigation mode)

- 0: Instruction executed successfully
- 10: Instruction is being processed
- 20: Mapping in progress
- 30: Localization and navigation in progress
- 99: Unknown input instruction

## Program Control Framework
- 101: Error closing program
- 102: Invalid startup request, program already running
- 104: No corresponding map available
- 105: No permission
- 106: System fatal error
- 107: Missing building or floor information
- 108: Map file corrupted
- 109: Instruction not supported in current mode
- 110: Failed to save map

- 600: Initialization pending
- 601: Running
- 602: Navigation cancelled
- 603: Navigation successful
- 604: Navigation failed
- 605: Navigation refused
- 620: Configuration failed
- 621: Emergency stop button triggered

- 901: Recharge successful
- 902: Infrared signal not detected
- 903: Charging station not found
- 904: Recharge timeout
- 905: Recharge in progress
- 906: Recharge cancelled

# Coordinate System

## 3D Cartesian Coordinate System (XYZ System)
- Right-hand coordinate system
- Middle finger → x-axis
- Index finger → z-axis
- Thumb → y-axis
- X-axis is defined as pointing forward

## Euler Angles
- Roll → rotation around x-axis
- Pitch → rotation around y-axis
- Yaw → rotation around z-axis
- Rotation is positive in counterclockwise direction

## Transforming Radar Point Cloud to Global Coordinate System

```
for (int i=0; i<x_laser.size(); i++) {
  xw[i] = xRP + (x_laser[i] * cos(heading)) - (y_laser[i] * sin(heading));
  yw[i] = yRP + (x_laser[i] * sin(heading)) + (y_laser[i] * cos(heading));
}
```

Where:
- xRP, yRP: Robot's coordinates in global system
- heading: Robot's current orientation (radians)
- x_laser, y_laser: Radar point cloud in robot coordinate system
- xw, yw: Transformed coordinates in global system

## Pixel Coordinates to World Coordinates
```
wx = origin_x + px × resolution
wy = origin_y + py × resolution
```

## World Coordinates to Pixel Coordinates
```
px = (wx − origin_x) ÷ resolution
py = (wy − origin_y) ÷ resolution
```
